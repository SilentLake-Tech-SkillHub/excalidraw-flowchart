# 流程规格说明

流程规格(`.flow.json`)用来画**细节流程**:你只写"有哪些阶段、每个阶段有哪些节点、节点之间怎么连",`scripts/flow.mjs` 负责排版和布线,画出来和手工构图是同一种风格。

## 写法

```json
{
  "title": "图的标题",
  "stages": [
    { "name": "阶段一", "nodes": [
      { "id": "a1", "label": "起点", "kind": "in" },
      { "id": "a2", "label": "要判断的事?", "kind": "gate" }
    ]},
    { "name": "阶段二", "nodes": [
      { "id": "b1", "label": "做某件事" },
      { "id": "b2", "label": "到此为止", "kind": "end" }
    ]}
  ],
  "edges": [
    { "from": "a1", "to": "a2" },
    { "from": "a2", "to": "b1", "label": "是" },
    { "from": "a2", "to": "b2", "label": "否" }
  ]
}
```

运行:

```bash
node scripts/flow.mjs xxx.flow.json          # 生成 xxx.skeleton.json
node scripts/render.mjs xxx.skeleton.json    # 渲染成 png / svg / excalidraw
```

## 节点类型 `kind`

| kind | 样子 | 用来表示 |
|---|---|---|
| `block`(默认) | 浅色填充的圆角块,颜色随阶段 | 一个普通步骤 |
| `in` | 斜线纹理的块 | 入口、起点 |
| `gate` | 紫色虚线块 | 判断,或需要用户确认的地方 |
| `end` | 橙色轮廓、不填充 | 终止、停下、不纳入 |
| `doc` / `stack` / `db` | 文档、纸堆、数据库图标,文字在图标下方 | 产物、一批资料、账本或数据库 |

## 排版与布线规则

- **阶段 = 一列**,从左到右;节点在列内从上到下,顺序就是你写的顺序。**把互相连线的节点尽量写在相邻的位置**,线最直。
- 同一列里下一个节点:直线向下,标签在箭头左边。
- 同一列里不相邻的节点:在框的右侧留白里绕行,标签放在框外右侧。
- 相邻两列之间:从节点右边出线,经过列间空隙,进入目标节点左边;一个节点有多条出线时,出口自动错开。
- 往前面的阶段回跳、或跨过一列以上:虚线,从列间空隙下到所有框的下方再绕回去。
- 列间距会按标签长度和连线数量自动加宽,不需要手调。
- 阶段的配色自动循环(蓝、绿、灰);紫色留给 `gate`,橙色留给 `end`。

## 写节点文字的建议

- 每个节点 2 行以内,每行不超过约 10 个汉字,超出会自动换行。
- 判断节点写成问句;分支的条件写在连线的 `label` 上,标签尽量不超过 6 个字。
- 同一列里不相邻的连线,标签位置比较挤,**把条件直接写进目标节点的文字里**更清楚(例如"联系不上\n停在提交前")。

## 示例

`examples/flows/` 里有两个完整例子:

- `apply-submit-gate.flow.json`:提交前的确认门禁,有判断、回路、终止。
- `search-role-verify.flow.json`:逐个核验岗位,多条分支汇入同一个写入节点。
